# สร้างภาพ เสียง คลิป และหนังด้วย Jude Code

รีสตาร์ต Jude Code เพื่อโหลดเครื่องมือใหม่ ใช้คีย์ OpenRouter เดิม:
`JUDECODE_OPENROUTER_API_KEY` หรือ `OPENROUTER_API_KEY` ไม่ต้องเปลี่ยนโมเดลหลักที่ใช้เขียนโค้ด

## ตัวอย่างคำสั่งในแชต

- “สร้างภาพโปสเตอร์ร้านกาแฟ อัตราส่วน 9:16 เลือกโมเดลจาก OpenRouter ให้ด้วย”
- “ใช้ภาพนี้เป็นเฟรมแรก สร้างคลิปเดินในป่า 5 วินาที เลือกโมเดลที่รองรับ”
- “สร้างเสียงบรรยายภาษาไทย: ยินดีต้อนรับสู่บ้านของเรา บันทึกเป็น MP3”
- “ทำหนังสั้น 3 ฉาก ฉากละ 5 วินาที เรื่องแมวเดินทางกลับบ้าน พร้อมเสียงบรรยายไทย แล้วรวมเป็น MP4”

Jude ใช้ `media_models` เลือกโมเดลและตัวเลือกที่รองรับ จากนั้นเรียก:

| Tool | ผลลัพธ์ |
|---|---|
| `media_image` | ภาพ PNG/JPEG/WebP; รองรับภาพอ้างอิงในเครื่องหรือ HTTPS |
| `media_audio` | ไฟล์ MP3 เสียงพูด/บรรยาย; เลือก model, voice, instructions ได้ |
| `media_video` | ส่งงานสร้างคลิป รับ job_id และใบรับงาน JSON ทันที |
| `media_video_status` | ตรวจงานครั้งเดียว ดาวน์โหลด MP4 เมื่อสำเร็จ |
| `media_movie` | รวมภาพนิ่ง/คลิปตามลำดับเป็นหนัง MP4 พร้อมเสียงบรรยายเสริม |

การทำหนัง: เขียนบท → แบ่งฉาก → สร้างภาพ/คลิปแต่ละฉาก → ตรวจงานจนเสร็จ → สร้างเสียง → ประกอบหนัง
คลิปเก็บเสียงเดิมไว้ เสียงบรรยายจะผสมเพิ่มโดยไม่ลดเสียงฉากอัตโนมัติ ภาพ/คลิปปรับขนาดพร้อมขอบดำให้สัดส่วนตรงกัน
`duration` ของแต่ละฉากใช้ตัดคลิปหรือค้างเฟรมสุดท้าย; เสียงบรรยายสั้นไม่ตัดหนัง แต่เสียงที่ยาวกว่าหนังจะถูกตัด

## ไฟล์และการทำต่อ

ผลลัพธ์และใบรับงานอยู่ที่ `~/.judecode/media/` ชื่อไม่ซ้ำ ไม่ทับไฟล์เดิม
JSON เก็บ job_id, สถานะ, path, และ usage/cost เมื่อ API ส่งกลับมา ไม่เก็บคีย์หรือ base64
หลังปิดโปรแกรมให้อ่านใบรับงาน แล้วเรียก `media_video_status(job_id=...)` เพื่อทำต่อ
ตรวจทุกประมาณ 30 วินาที อย่าส่ง `media_video` ซ้ำเพื่อรอผล
ถ้า submit หมดเวลาก่อนรับ job_id ให้ตรวจ Activity ของ OpenRouter ก่อนสร้างใหม่ เพราะงานเดิมอาจถูกคิดเงินแล้ว
สถานะ failed/cancelled/expired ต้องรายงาน ไม่สร้างซ้ำโดยอัตโนมัติ

## ตั้งค่าเพิ่มเติมใน .env

```dotenv
JUDECODE_MEDIA_OUTPUT_DIR=/absolute/path/to/media
# ค่าเริ่มต้นประหยัด (แก้ได้); ตรวจ availability/pricing ด้วย media_models
JUDECODE_MEDIA_IMAGE_MODEL=black-forest-labs/flux.2-klein-4b
JUDECODE_MEDIA_VIDEO_MODEL=x-ai/grok-imagine-video-1.5-lite
JUDECODE_MEDIA_AUDIO_MODEL=
```

เสียงใช้ VOICE_TTS_MODEL และ VOICE_NAME เดิมเป็นค่าเริ่มต้น หากเปลี่ยนโมเดลต้องเลือก voice ที่โมเดลนั้นรองรับ
การสร้างเพลงหรือเสียงเอฟเฟกต์ขึ้นอยู่กับโมเดลเสียง ไม่ใช่ทุกโมเดล TTS จะทำได้
การสร้างภาพและเสียงเป็น synchronous; วิดีโอเป็น asynchronous

## ติดตั้งตัวประกอบหนัง

ใช้ FFmpeg ที่มีใน PATH หรือใน Python environment ของ Jude:

```sh
python -m pip install -r requirements-media.txt
```

โมดูลนี้มี binary FFmpeg จึงไม่ต้องใช้บัญชีบริการอื่น
หนังรองรับสูงสุด 30 ฉาก ฉากละ 0.1–120 วินาที; ขนาดด้านละ 128–3840 และต้องเป็นเลขคู่
ภาพอ้างอิงไม่เกิน 20 MiB; ไฟล์จาก API ไม่เกิน 256 MiB ต่อไฟล์
งานสร้างสื่อมีค่าใช้จ่ายจาก OpenRouter แยกจากค่าแชต; usage ส่งกลับเมื่อมีข้อมูล แต่ยังไม่รวมใน budget/token tracker ของ Jude
ค่าตัวเลือกที่โมเดลไม่รองรับจะทำให้ API ปฏิเสธ ตรวจรายการปัจจุบันด้วย media_models เสมอ

## โหมดผู้กำกับแบบประหยัด

สั่งได้ว่า “ทำคลิปแมวกลับบ้าน 3 ฉาก เน้นประหยัด ตัวละครต่อเนื่อง เสียงบรรยายไทย”
Jude จะเขียน storyboard และ continuity bible (ตัวละคร เสื้อผ้า อุปกรณ์ สถานที่ แสง ทิศทางการเคลื่อนไหว)
แล้วใช้ `director_plan` บันทึกฉากเรียงลำดับ ก่อนเรียก `director_step` ทีละขั้นจนได้ MP4

- ค่าเริ่มต้นทุกฉากเป็นวิดีโอเคลื่อนไหว (`mode=video`) ใช้ Grok Imagine 1.5 Lite ที่ 480p ไม่มีเสียงจากโมเดลคลิป; FLUX.2 Klein 4B ใช้สร้างภาพอ้างอิง/เฟรมแรก
- คำสั่งวิดีโอ/VDO/หนังสั้น/ตัวอย่างหนัง รวมถึงงานเน้นประหยัด ต้องใช้คลิปเคลื่อนไหว ไม่ใช้ภาพนิ่งใส่คำบรรยายหรือแพน/ซูมแทน
- `mode=still` ใช้ได้เฉพาะผู้ใช้ขอภาพนิ่งหรือสไลด์ โดยระบุ `allow_stills=true` ใน `director_plan`; หากไม่ระบุระบบจะปฏิเสธแผนภาพนิ่งก่อนมีค่าใช้จ่าย
- หาก API วิดีโอล้มเหลวหรือไม่ทราบผล ให้รายงานข้อผิดพลาดและสถานะงานเดิม ไม่เปลี่ยนเป็นภาพนิ่งหรือส่งงานคิดเงินซ้ำเอง
- เสียงใช้ VOICE_TTS_MODEL/VOICE_NAME เดิม (MAI เสียงไทย Nattapong โดย default); narration เป็นบทที่อ่านจริงรายฉาก
- link=cut ส่งภาพฉากแรกเป็น reference รักษาเอกลักษณ์; link=continue ส่งเฟรมท้ายคลิปก่อนหน้า (หรือภาพก่อนหน้า) พร้อมภาพฉากแรก
- สร้างภาพก่อนแล้วส่งเป็น first_frame ของคลิป; เก็บ job_id และ poll งานเดิม ไม่ submit ซ้ำ
- วัดความยาวเสียงจริงก่อนรวมแต่ละฉาก ถ้าเสียงยาวกว่าฉากจะค้างเฟรมท้ายเพิ่ม ไม่ตัดบทพูด; เกิน 120 วินาทีต้องแบ่งฉาก
- รวมฉากที่มีเสียงบรรยายแล้วตามลำดับเป็นหนัง; รองรับ 16:9, 9:16, 1:1
- ไม่มี automatic upgrade ไปโมเดลแพง และไม่มีการลอง paid generation ซ้ำเมื่อผลไม่แน่นอน

แผนและสถานะอยู่ `~/.judecode/media/projects/<project_id>.json`
ใช้ `director_status(project_id)` ดูงานและขั้นถัดไปหลัง restart แล้ว `director_step(project_id)` ทำต่อ
หลังอัปเดตต้อง restart JudeCode เพื่อโหลดคำสั่งและ tools ใหม่ แผนเก่าที่มีฉากภาพนิ่งแต่ไม่มี `allow_stills=true` จะหยุดให้ตรวจแก้ storyboard ตามคำขอจริงก่อนทำต่อ; ไม่แปลงแผนหรือสร้างคลิปใหม่ให้อัตโนมัติ และต้องรักษา job_id/receipts เดิม
หาก pending operation ค้างจาก timeout/crash ระบบจะหยุดเพื่อกันคิดเงินซ้ำ: ตรวจ receipt และ OpenRouter Activity
แล้วกู้ asset/job_id เข้าแผนที่บันทึกไว้หลังตรวจยืนยัน (ยังไม่มีปุ่มกู้อัตโนมัติ); ห้ามสร้าง project ใหม่เพื่อเลี่ยงสถานะนี้
การล็อกการทำงานต่อ project ใช้ POSIX file lock (macOS/Linux)

ความต่อเนื่องเป็นการชี้นำด้วย prompt/reference ไม่รับประกันหน้าตาและท่าทางตรงทุกเฟรม ต้องตรวจผลงาน
ระบบนี้ยังไม่มี lip sync, ซับ หรือการวางฟอนต์ไทยอัตโนมัติ และไม่ได้วัดคุณภาพด้วยสายตาให้เอง
`receipts` เก็บค่าใช้จ่ายที่ provider รายงาน ไม่ใช่ยอดรวมสมบูรณ์และยังไม่เชื่อม `/budget`
