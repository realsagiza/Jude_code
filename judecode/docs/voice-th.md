# พูดคุยภาษาไทยกับ JudeCode ผ่าน OpenRouter

ใช้ได้ในหน้าจอหลัก `judecode` (TUI) เท่านั้น เปิดโปรแกรมใหม่หลังอัปเดต
ใช้ OpenRouter สำหรับทั้งถอดเสียงและสร้างเสียง โดยใช้ API key เดิม
โมเดลเขียนโค้ดและประวัติสนทนายังทำงานตาม config เดิม

## สนทนาต่อเนื่องโดยไม่ใช้คีย์บอร์ด

เปิดโปรแกรมใหม่ด้วย `judecode --voice` หรือใน TUI พิมพ์ `/voice on` ครั้งเดียว
Jude จะทักด้วยเสียง จากนั้นพูดสั่งงานได้เลย ไม่ต้องกดปุ่มอัดเสียงหรือ Enter
หยุดพูดประมาณ 2.1 วินาที ระบบจะส่งคำพูดเป็นคำสั่งให้ agent อัตโนมัติ
Jude ทำงานจริงด้วยเครื่องมือเดิม แล้วพูดผลลัพธ์หรือคำถามกลับ
แล้วรอฟังต่อ คุณตอบคำถามและสั่งงานรอบถัดไปด้วยเสียงได้เลย

- พูด **“หยุดงาน”** หรือ **“หยุดก่อน”** ขณะ Jude ฟัง: ขอหยุด agent และล้างคำสั่งที่รออยู่ แล้วฟังคำสั่งใหม่ต่อ
- พูด **“ปิดโหมดเสียง”** หรือ **“เลิกคุย”**: ขอหยุดงาน ล้างคิว ปิดไมค์และจบโหมดด้วยเสียง
- `/voice off`, `/voice stop` หรือ Esc ใช้หยุดโหมดด้วยคีย์บอร์ดได้หากต้องการ
- `/voice status` ดูสถานะ; `/voice read` อ่านคำตอบอย่างเดียวแบบรุ่นก่อน

**เป็นการผลัดกันพูด:** ขณะ Jude พูดออกลำโพง ไมค์จะพักเพื่อป้องกันเสียงวนกลับเป็นคำสั่ง
รอ Jude พูดจบก่อนพูดต่อหรือพูดปิดโหมด ยังไม่รองรับการพูดแทรกระหว่างเสียงตอบกลับ
ระหว่างรอถอดเสียง ระบบฟังต่อ หากพูดต่อจะรวมเสียงแล้วถอดเป็นคำสั่งเดียวก่อนส่ง agent
ระหว่าง agent ทำงานและไม่ได้พูด ระบบยังฟังได้; คำสั่งใหม่จะเข้าคิว ส่วน “หยุดงาน” จะขอหยุดทันทีหลังถอดเสียง
การหยุดเครื่องมือที่กำลังรันยังขึ้นกับระบบหยุดงานเดิม ไม่รับประกันฆ่า subprocess ทันที

ใช้ WebRTC VAD ตรวจเสียงพูดในเครื่อง ช่วงเงียบไม่เรียก STT
เก็บเสียงแต่ละช่วงไม่เกิน 90 วินาที; ถ้ายาวถึงเพดานจะไม่ส่งคำสั่งที่ขาดกลางประโยค ต้องพูดใหม่ให้สั้นลง
เสียงที่รวมจากการพูดต่อจำกัดรวม 120 วินาที
ต้องเงียบประมาณ 2.1 วินาทีเพื่อจบคำสั่ง; เสียงคนอื่น/ทีวีอาจถูกนับเป็นคำสั่งได้
โหมดนี้ส่งข้อความจากเสียงโดยไม่รอให้ตรวจหรือกด Enter ตามการเปิดใช้งานของคุณ
หากไมค์ล้มเหลวซ้ำ 3 ครั้ง โหมดจะหยุด; ถ้า API สร้างเสียงใช้ไม่ได้ อาจแจ้งได้เฉพาะบนหน้าจอ

ติดตั้งส่วนเสียงใน environment ที่รัน JudeCode (ติดตั้งบนเครื่องนี้แล้ว):

```sh
python -m pip install -r requirements-voice.txt
judecode --voice
```

โหมดเดิม `/listen 8` ยังใช้ได้เมื่อต้องการอัดเป็นข้อความรอตรวจก่อน Enter
การพิมพ์ข้อความเองระหว่างโหมดสนทนาจะหยุดโหมดเพื่อกลับไปใช้คีย์บอร์ด

## ตั้งค่า

ตั้งใน `.env` เดิมของ JudeCode (ไม่ต้องมีคีย์ OpenAI แยก):

```dotenv
JUDECODE_OPENROUTER_API_KEY=your-openrouter-key
JUDECODE_VOICE_STT_MODEL=openai/gpt-4o-mini-transcribe
JUDECODE_VOICE_TTS_MODEL=microsoft/mai-voice-2.1-flash
JUDECODE_VOICE_NAME=th-TH-Nattapong:MAI-Voice-2.1-Flash
JUDECODE_VOICE_SAMPLE_RATE=24000
JUDECODE_VOICE_END_SILENCE_MS=2100
JUDECODE_VOICE_MAX_UTTERANCE_SECONDS=90
JUDECODE_VOICE_VAD_MODE=1
```

รองรับ `OPENROUTER_API_KEY` เป็นค่า fallback เช่นเดียวกับระบบเดิม
STT ส่ง language hint `th`; ชื่อเสียงและภาษาที่รองรับขึ้นกับโมเดลที่เลือก
โหมดสนทนาเล่น PCM 16-bit mono แบบสตรีมทันทีที่ข้อมูลมาถึง; /voice read ยังใช้ WAV
หากเปลี่ยนโมเดลให้ตั้งชื่อเสียงและ sample rate ตรงกับ provider
เสียงอ่านเฉพาะคำตอบสุดท้าย ข้าม tool output และโค้ดใน fenced blocks
โหมดสนทนาแบ่งคำตอบยาวเป็นหลายช่วงเพื่อพูดครบ ส่วน `/voice read` จำกัดประมาณ 3,000 ตัวอักษร

macOS: อนุญาต Microphone ให้ Terminal/iTerm ที่ใช้งาน เล่นเสียงด้วย `afplay` ที่ติดมากับระบบ
Windows/Linux: ติดตั้ง FFmpeg ให้คำสั่ง `ffplay` อยู่ใน PATH
Linux อาจต้องติดตั้ง PortAudio ของระบบเพิ่มสำหรับ sounddevice

เสียงไมค์ถูกส่งไป OpenRouter เมื่ออัดเสร็จ; คำตอบถูกส่งไปสร้างเสียงเมื่อเปิด voice
เสียงอัดอยู่ในหน่วยความจำ; ไฟล์เล่นเสียงเป็นไฟล์ชั่วคราวและลบหลังเล่นหรือยกเลิก
ข้อความที่ส่งอัตโนมัติหรือกดส่งถูกเก็บในประวัติตามระบบสนทนาเดิม
ค่า STT/TTS เพิ่มจากการคุยปกติ และ **ยังไม่รวมใน `/budget`**; ตรวจยอดจริงใน OpenRouter
ยกเลิกหลังส่ง API แล้วอาจยังมีค่าใช้จ่ายของคำขอนั้น

## ลดความหน่วงและการตัดประโยค (2026-10-13)

- เปลี่ยน TTS default เป็น MAI-Voice-2.1-Flash เสียงไทย Nattapong และเล่น PCM แบบสตรีม
- เอา TTS “รับคำสั่งแล้ว” ทุกรอบออก เพื่อไม่เสีย API round-trip และเวลาพูดเพิ่ม
- แบ่งคำตอบตามช่องว่าง เป้าหมายประมาณ 500 ตัวอักษร (สูงสุด 2,500 หากไม่มีช่องว่าง) เพื่อเริ่มเสียงได้เร็วขึ้น
- ค่าเริ่มต้นรอเงียบ 2.1s; ตั้ง `JUDECODE_VOICE_END_SILENCE_MS=3000` หากเว้นคิดนาน (รองรับ 600–5000ms)
- VAD mode=1 เก็บเสียงพูดเบามากกว่า mode=2 เดิม แต่เสียงรบกวนอาจถูกนับเป็นเสียงพูดมากขึ้น
- ไม่ตัดส่งอัตโนมัติที่ 30s อีก; ค่า cap 90s ตั้งได้ 10–120s และถึง cap จะไม่ execute ข้อความครึ่งประโยค
- ส่ง vocabulary hint ให้ OpenAI STT ผ่าน provider options; ตั้ง `JUDECODE_VOICE_STT_PROMPT` เพื่อเพิ่มชื่อเฉพาะของงาน (provider อื่นอาจไม่ใช้ hint)
- `/voice status` แสดง STT duration และ TTS time-to-first-audio ล่าสุด ไม่ใช่ความหน่วง end-to-end

วัดด้วยประโยคไทยสังเคราะห์หนึ่งประโยคผ่าน API จริง: Gemini 3.8 Flash TTS เริ่มส่งเสียง ~3.7s,
MAI-Voice-2.1-Flash ~1.9s; ค่าเหล่านี้เป็นตัวอย่าง ไม่ใช่ SLA และไม่ได้วัดไมค์/ลำโพงจริง
STT mini และ full ในตัวอย่างนั้นให้ข้อความเหมือนกัน จึงคง mini ไว้ ไม่อ้างว่าเพิ่มโมเดลแล้วจะแม่นขึ้นเสมอ

ยังต้องรอ STT และงาน agent ก่อนคำตอบ; OpenRouter ที่เชื่อมอยู่นี้เป็น STT + agent + TTS แยกกัน
ไม่ใช่ end-to-end Realtime และไม่มี semantic end-of-turn หรือ acoustic echo cancellation
ยังไม่สามารถรับประกันประสบการณ์เทียบเท่า Codex ได้ จากเอกสาร OpenAI มี semantic VAD ที่ประเมินการจบจากความหมาย
แต่ไม่ได้พิสูจน์ว่า Codex ใช้ implementation ใด และยังไม่ได้ต่อบริการนั้นใน JudeCode
