# การทำงานโครงการต่อเนื่องบน Mac และ Ubuntu

AgentEngine ทั้งสองแพลตฟอร์มมี project_plan, project_verify และ project_pause
มี project_revise_checks สำหรับแก้คำสั่งทดสอบผิดโดยเก็บเกณฑ์เดิมและประวัติแก้ไข
และ project_resolve_failure สำหรับปิด error เก่าพร้อมเหตุผลหลัง checks ทั้งหมดผ่าน

สำหรับงานหลายฟีเจอร์ โมเดลต้องลงทะเบียนเป้าหมาย project root และเกณฑ์ตรวจรับทุกข้อ
ก่อนลงมือ งานที่แก้หลายไฟล์หรือเพิ่ม task จะถูกบังคับลงทะเบียนก่อนจบ
รายการนี้บันทึกใน native transcript และคงอยู่เมื่อผู้ใช้ส่งข้อความเพิ่มเติม
เมื่อ restore จะตรวจ checks ใหม่เพราะไฟล์อาจเปลี่ยนระหว่างปิดโปรแกรม
ใช้ /new เพื่อแยกโครงการ และ /continue เพื่อทำต่อจากรายการเดิม

project_verify รันคำสั่งตรวจรับที่ลงทะเบียนจริงใน project root ผ่าน shell permission
และ safety เดิม แต่ละคำสั่งมี timeout 120 วินาที; หยุดเริ่มคำสั่งเพิ่มเมื่อรอบตรวจเกิน
300 วินาทีหรือผู้ใช้สั่งหยุด การยกเลิกไม่ฆ่าคำสั่งปัจจุบันทันที ไม่ replay หลัง crash
จนกว่าจะตรวจผลที่ไม่แน่ชัด งาน remote ต้องระบุ SSH/container checks ให้ถูกปลายทาง

เขียน/แก้ไข/รันเครื่องมือที่อาจเปลี่ยนงานจะยกเลิกผลผ่านเดิม ต้องตรวจใหม่ก่อนจบ
โมเดลตอบข้อความสุดท้ายทั้งที่ยังไม่ครบจะถูกส่งกลับให้ทำต่อสูงสุดสามครั้งโดยไม่มี
ความคืบหน้าที่ผ่านการตรวจ รอบ verification จำกัด 12 ครั้งต่อคำขอ การทำ action
และได้ผลเดิมซ้ำหกครั้งหยุดให้ตรวจสาเหตุ /continue เปิดงบรอบใหม่โดยคงงานเดิม

Telegram ส่งสถานะจริงเมื่อ failed/unverified/paused แทนข้อความสำเร็จที่โมเดลอ้าง
บน Mac แสดงผลสถานะจริงและเก็บไว้เป็นข้อความสุดท้ายเช่นกัน

ข้อจำกัด: ขอบเขตและคุณภาพ checks ยังขึ้นกับการแตกสเปกของโมเดล ต้องครอบคลุม
business flow, integration และ browser E2E; exit code 0 ของ checks ที่อ่อนเกินไป
ไม่รับประกันระบบครบทุกข้อ ไม่มีการรับประกันว่างาน POS ทั้งระบบจะจบจากทุก prompt
ไม่มีการเพิ่ม browser runner อัตโนมัติ ไม่มีการเปลี่ยนทุกข้อความเป็น scheduled job
และไม่มีการทำงานต่อหลัง restart โดยไม่ตรวจ interrupted actions ก่อน
